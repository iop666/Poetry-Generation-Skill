## Phase 0 细节：资料底座的三个来源

1. **韵书（硬约束）**：平水韵 106 韵全表，繁体原文 + OpenCC 转写的简体索引。
   索引里每个字带 `ping`／`ze` 两组韵部，多读字两组并存 —— 这是后面「多读放宽」的基础。
2. **格律（规则）**：王力《诗词格律》体系（四式、粘对、孤平、拗救），落成 `格律规则.md` 与 `gedou.py` 的 `TEMPLATES`。
3. **作品（语感）**：13 首唐诗，覆盖 五绝／七绝／五律／七律／古绝／仄韵，每首标注韵部与一处技术动作。

## Phase 1 细节：知识库不是语录本

四个文件各自的「可执行」落点：

- `格律规则.md` → 每类病名后标注引擎检查名，规则与代码一一对应。
- `对仗句式.md` → 20 组对类 + 5 个 2-2-3 句式模板，写作时直接取用。
- `意象词典.md` → 每个意象给「情绪坐标 / 有效搭配 / 滥用风险」，并附「反套路清单」。
- `典故库.md` → 每条给「本义 → 用法 → 反用」，加三条用典纪律。

## Phase 2 细节：判定边界比判定能力更重要

引擎**能判**：出律、失对、失粘、落韵（出韵）、撞韵、孤平、三平调、三仄尾、重字、句式与字数、词牌平仄与词韵。
引擎**不判**：合掌、四平头、摞眼、意象陈腐、情理不通、工拙高下——一律标「需人工复核」。

这不是偷懒：把「能判的判死、不能判的说清」，才不会出现「格律合格就当真合格」的误判。

## Phase 3 细节：一次交付的固定格式

每首作品交付三件套（对应方案要求的输出样式）：

1. **作品**（正文，含标题与体裁）
2. **创作说明**（取象、结构、用意）
3. **格律审查报告**（逐字平仄表 + 韵脚表 + 对仗粗检 + 结论）

`05_创作库/*.md` 即是这个格式的实例，可直接作为交付模板复用。

## Phase 4 现状与差距

已做：

- 13 首名篇对读，逐首给出「最值得学的一处技术动作」。
- 1 组「平庸稿 → 重构稿」的完整对照（含三条重构手段）。
- 同一主题三版（婉约／豪放／清远）的并置实验。

未做（下一步）：

- **百首规模**的标注与对读（当前 13 首只是样本）。
- **修改史**：同一首诗的第 1 稿到第 N 稿留存与差异记录（文学性提升主要靠这一步）。
- **人工评审分**：目前「文学性」只有清单式自查，没有评分与对照实验。
- **词牌扩容**：现仅 3 个词牌，常用词牌约 100 个，需按使用频率逐步补谱。

## 里程碑判定

- Phase 0–3 完成 = 方案里「能写、能查、能交」的闭环成立。
- Phase 4 完成 = 方案里「写得好」的闭环成立，这部分**不能靠引擎**，只能靠对读量与修改量。
