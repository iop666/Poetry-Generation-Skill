## 一、v1 的三个具体机制（附源码证据）

### 机制一：`fits()` 无条件放行两读字

```python
# engine/gedou.py v1，第 196–201 行
def fits(ch: str, expect: str) -> bool:
    """字 ch 是否满足平仄要求 expect（'平'/'仄'）；多读字与未收录字放宽。"""
    t = LEX.tones(ch)
    if not t:
        return True
    return expect in t
```

`LEX.tones(ch)` 对「平仄两收」的字返回 `{"平","仄"}`，于是 `expect in t` **恒为真**。
无论该字在这个句子里实际读什么、无论语义要求哪个读音，一律通过。

这不是「放宽」，这是**让检查在该位置失效**。

### 机制二：`realized()` 按谱还原读音

```python
# engine/gedou.py v1，第 295–307 行
def realized(ln: str, pat: str) -> list:
    """按「谱 允许时取与之相符的读音」还原实际平仄"""
    ...
    elif len(t) == 2:
        if exp == "平":
            out.append("平")     # ← 谱要求平，就说是平
        else:
            out.append("仄")     # ← 谱要求仄，就说是仄
```

函数名是 `realized`（实际平仄），注释写「按谱还原读音」。它算出来的不是实际读音，是**谱的复印件**。
这个结果随后被用于三平调／三仄尾判定 —— 也就是用「照抄谱」的结论去检验「是否合谱」。

### 机制三：孤平按「可读为平」计数

```python
# engine/gedou.py v1，第 318 行
ping = [c for c in ln[:-1] if "平" in LEX.tones(c)]
if len(ping) == 1:
    errors.append(... "犯「孤平」")
```

只要一个字**可以**读平，就算作平声字。于是孤平判定用的不是读音，是「有没有这个可能性」。

## 二、v1 报告其实已经承认了这件事

v1《实施报告》第五节第 3 点原文：

> 「引擎对多读字取『可读为某声即通过』，同时对三平调／三仄尾采用『按谱还原读音』判定。
> 代价是个别处可能放过，收益是不再把好诗判成坏诗。」

这段话把机制说清楚了，但把性质说轻了：它描述为「代价是个别处放过」，
实际是**874 个字的平仄判定整体失效**。这不是「个别处」。

## 三、量化：失效面有多大

| 指标 | 数值 | 说明 |
|---|---|---|
| 韵书字数 | 8361 | 简体去重 |
| 平仄兼收字数 | **874** | 占 10.5%，这些字在固定位的平仄判定全部失效 |

每 10 个字里就有 1 个"怎么读都对"。一首七绝 28 字，期望约有 3 个字落在这个池子里。

## 四、v2 的处理

### 4.1 判定顺序（按审核要求）

审核要求：`语义识别 → 历史读音判断 → 韵书查询 → 格律校验`。

v1 的实际顺序：`格律期望 → 韵书查询 → 凑`。
v2 的实际顺序：

```
韵书查询（读出全部候选读音）
   ↓ 候选唯一 → 直接判定，与格律比对（格律只比对，不定音）
   ↓ 候选为平仄两收
       ├─ 命中「词组/义项」表 → 按义定音，记 PASS/FAIL，并注明依据
       ├─ 命中白名单 → 记 FLEXIBLE_READING（放宽但不计为通过）
       └─ 都不命中 → 记 UNKNOWN（待人工确认）
   ↓ 韵书未收录 → 记 UNKNOWN
```

关键改动在最后一行：**格律不再参与"选哪个音"**。格律只能在读音已定之后判断对错。

### 4.2 白名单：11 个字，且明说是政策不是考据

`engine/yunshu.py`：

```python
POLICY_LENIENT = frozenset("望看听忘凭漫叹教令醒过")
```

收录条件（写在代码注释里）：

- a. 《平水韵》中平声韵与仄声韵两收；
- b. 平仄两读在诗律工具书中历来被视为「又音」，非严格义项对立；
- c. 高频，若一律判 UNKNOWN 会使绝大多数唐宋名篇无法判定。

**必须如实说明本项的弱点**：这 11 个字没有逐字给出《广韵》反切与义训对勘，
它的性质是**工程政策**，不是考据结论。引擎在输出中把它标为 `FLEXIBLE_READING`（符号 `≈`），
并在每处注明「两读字按又音放宽，未计为通过」，就是为了让审核者一眼看到这不是 PASS。

从 874 降到 11，是 1.3%。剩下的 863 个字不再放行。

### 4.4 效果验证：李商隐《锦瑟》

这是最能说明改动价值的一例。

第 2 句「一弦一柱思华年」末三字 思／华／年：

- 若「思」读平（动词，思念）→ 末三字全平 → **三平调**（近体大忌）
- 若「思」读去（名词，情思）→ 末三字 仄平平 → 合律

v1 的做法：`realized()` 按谱取音 —— 谱要求仄就报仄，于是这首名作「合格」。
这是**替作者选了一个让检查通过的音**。

v2 的输出（`tests/04_polyphone_boundary.json` M01）：

```
? 第2句句末「思华年」是否三平调，因读音未定无法判定
```

不判违律，也不判通过。**这才是「不能确定就返回 UNKNOWN」。**

## 五、仍未解决的（为什么只能给 PARTIAL）

| 缺口 | 影响 | 补法 |
|---|---|---|
| 无义项级消歧表 | 28 字 48 处停在 UNKNOWN，占名篇判定的主要噪声 | 逐字建「字 → 义项 → 读音」表，每条附《广韵》《集韵》反切与诗例 |
| 白名单 11 字无考据支撑 | 可能被审核者质疑为「另一种选音」 | 逐字补反切与义训对勘，或撤下白名单改为一律 UNKNOWN |
| 词组表未建 | 「艰难」「不胜」这类固定复合词本可确定，现在仍是 UNKNOWN | 建常用词组表，每条注明是固定词而非临时搭配 |
| 繁简归并伪两读 33 字未拆 | 这些字的「两读」是转写造成的，不是真两读 | 需按繁体字分别判定，须保留原文而不经 t2s |

第 2 项是最大的风险点。如果外部审核认为白名单不可接受，正确做法是把它清空，
代价是名篇判定的 UNKNOWN 数会从 48 处升到约 60 处。**这个取舍应由审核者决定，不由执行方决定。**
