### 2.2 关键决策与理由

**决策一：不覆盖 `author_name`，另开 `author_canonical`。**
原始著录名本身是证据（《古詩紀》题「簡文帝」、《文選》题「王仲宣」），改写后无法回溯底本。故 RAW 层保留原值，新增规范化列与映射表，两张表都可查、可撤。

**决策二：用《陶淵明集》＋《昭明文選》补六朝，而不是换一部总集。**
《先秦漢魏晉南北朝詩》（逯欽立）有现代版权，全文不可取；《古詩紀》转录残缺已确认。陶集与文選均为公有领域，且维基文库有分页全文。**代价**：文選是选本（陶詩仅 7 首），陶集是别集（一人），二者相加仍不等于六朝全集——这是选本与别集的固有边界，不是执行不到位。

**决策三：逐字转换 + 可回环校验，不用 OpenCC 整串转换。**
实测 OpenCC 的 t2s 词典含异体归并，`张榘`→`张矩`，会把 109 首作品并到另一个人名下。改为逐字转换并要求 `s2t(t2s(c)) == c`，只接受真正的繁简对应。

**决策四：陶集异文单列 `SOURCE_MARKED_VARIANT`。**
底本的 `{{另|A|B}}` 是整理者明示「A，一作 B」，属**直接证据**；与「同作者同题、文本不同」的程序推测候选不是一回事，不能混为一谈。

## 5. 技术实现

### 5.1 陶集解析（`fetch_tao.py`）

底本版式：

```
{{header|title=歸園田居|section=六首|author=陶淵明}}
<onlyinclude>
===其一===
<poem>
少無適俗{{另|韻|願}}，性本愛丘山。
```

处理链：`header` 取题／节数 → 去 `<onlyinclude>`/`<poem>`/`<div>` 标签 → **逐行**处理 `{{另|A|B}}`（取 A、记 B）→ 清其余模板 → 按 `===其N===` 分节 → 每节一条记录，`volume` 记卷次。

### 5.2 作者规范化（`author_canon.py`）

判定顺序：非人名 → 谥号 → 字号 → 异体 → 繁简。三个必须写死的细节：

1. **映射表内的值是繁体，仍要转简**。否则 `蕭綱`（谥号映射结果）与 `萧纲`（繁简结果）会并存成两人。
2. **尾部数字不能盲剥**。`王锡九`、`刘锡五`、`张元一` 是真名，剥成 `王锡`/`刘锡`/`张元` 会并错人。改为「剥后能命中谥号/字号表才剥」（`簡文帝三` 属此类）。
3. **OpenCC 要逐字且校验回环**。整串转换会把 `张榘` 并成 `张矩`。

### 5.3 跨源核对（`crosscheck_100.py`）

- 上游 A：chinese-poetry（GitHub 整理本）；上游 B：维基文库《唐詩三百首》逐篇页（社区转录）。**非镜像**。
- 匹配：标题索引（去括注、去「並序」）∪ 正文前 8 字索引，取整体相似度最高者，阈值 0.80。
- 空响应退避重试 3 次（3s/6s/9s）。

### 5.4 边界与兼容

- `works` 新增列 `author_canonical`，**旧查询不受影响**（旧列未动）。
- `author_alias` 为独立表，可整表重建（`author_canon.py` 幂等）。
- `variant_candidates` 新增 `SOURCE_MARKED_VARIANT` 类别，旧类别语义不变。

## 11. 自我审计（六问）

1. **`author_canonical` 会不会把两个不同的人并成一个？** 会。同名不同人（如两个「王锡」）在字符串层面无法区分，本轮已实测并修掉 3 组误并，但**没有机制保证剩余 20,326 个名字无误**。
2. **陶集 124 篇是否等于陶诗全部？** 不是。通行本陶诗约 120–130 首，本库按「页—节」计 124 条，组诗分节粒度与学界计数口径不同，**不能直接当「陶诗全集」引用**。
3. **文選 357 篇的朝代是推定的**。`ERA` 表按《文選》编次与通行分期填写，**未逐人核史传**，属推定。
4. **MATCH_VARIANT 的拆分规则是否会把实质差异误判为异体？** 可能。规则是「逐位折形后相同」，对「一字换一异体」成立，但若两版各错一字恰好折形相同，会漏判。
5. **`SUSPECT_NOTE_MIXED` 的 222 条是关键词命中**，可能有漏（校记写法多样），也可能有误伤（正文本身含「四部叢刊」字样者极少但非零）。
6. **本轮所有「修好的 bug」都是我自己发现、自己修的**，没有第三方复现。独立审核仍应重跑 §6.1 的命令。
