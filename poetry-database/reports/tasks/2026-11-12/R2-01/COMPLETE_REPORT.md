### 3.2 重要决策

**决策 1：用公有领域总集补空白，不用现代版权总集。**
《先秦漢魏晉南北朝詩》《全遼金詩》均为现代编校，有版权；
改取《古詩紀》（明·馮惟訥）、《中州集》（金·元好問）、《明詩綜》（清·朱彝尊）、《晚晴簃詩匯》。
代价：四庫本**无标点**，无法判体；这对体裁统计是硬伤（见 §6.4），比「完全没有」好，但不如现代校点本。

**决策 2：四库本无标点时，体裁标「未定」，不标「古体诗」。**
按句长判体会把 15,866 条全部压成「古体诗」，那是伪造结论。宁可标「未定」并单列。

**决策 3：核对用两个不同上游，但不下 `EDITION_VERIFIED`。**
chinese-poetry 与维基文库是不同整理者，可判「两版一致」；
但无法证明二者不同源，也无法指出印本页次，故停在 `TEXT_CROSSCHECKED`。

**决策 4：异文与归属只分类、不裁决。**
程序不判断「哪一版对」「谁是真作者」，全部留 `UNRESOLVED`。

## 6 技术实现

### 6.1 schema v2

```sql
-- works 新增 9 列
text_punct         -- 保留原始标点的正文（text_raw 保留原始分行）
genre_verified     -- 人工确认体裁（本轮全 NULL）
dynasty_verified   -- 史传核验朝代（本轮全 NULL）
quality_grade      -- PARSED / SOURCE_TRACEABLE / TEXT_CROSSCHECKED / EDITION_VERIFIED
upstream           -- 上游标识
record_locator     -- 分片文件#序号 或 卷次
juan               -- 卷次
base_edition       -- 底本说明
crosscheck_result  -- MATCH / DIFF / UNKNOWN

-- 新表
provenance, attribution_candidates, variant_candidates, text_crosscheck
```

**为什么必须显式列名**：`schema_v2` 之后 `works` 从 27 列变 36 列，
原 `INSERT OR REPLACE INTO works VALUES (?,…×27)` 会因列数不符直接报 `OperationalError`。
本轮已改为 `INSERT INTO works (col,…) VALUES (?,…)`，并把列名收在 `COLS` 常量里。

### 6.2 三种版式解析器

| 版式 | 书籍 | 判据 |
|---|---|---|
| `skqs_anchor` | 古詩紀 / 明詩綜 / 中州集 | `{{SK anchor|X}}` 状态机：朝代段→作者→篇题→正文 |
| `heading_poem` | 晚晴簃詩匯（少数卷） | `==作者==` / `===篇题===` / `<poem>` |
| `plain_anthology` | 晚晴簃詩匯（多数卷） | 缩进行：短名＋次行小传＝作者；短行无标点＝篇题；含标点＝正文 |

**作者判定的三次返工**（全部有真实数据佐证）：

| 轮次 | 问题 | 证据 | 修法 |
|---|---|---|---|
| 1 | 把《彈歌》「斷竹續竹飛土逐宍」当作者 | 卷 001 | 加小传特征正则 `字X/進士/處士` |
| 2 | 魏卷作者为空（「陳思王植」无小传） | 卷 024 | 加裸名规则 |
| 3 | 「上責躬詩」（小題）被当作者 | 卷 024 | 区分「待完成篇目的短行＝小題」 |
| 4 | 「钦定四库全书」485 条、「郊庙歌辞」304 条被当作者 | 作者统计 | 加 `AUTHOR_STOP` 与 `norm_author` |

### 6.3 数据流程

```
discover_ws_series.py  → sources/ws_pages.json (791 页)
        ↓
fetch_ws_series.py     → raw/books/<series>/<vol>.wikitext  (+ audit/ws_fetch_log.jsonl)
        ↓
ws_to_json.py          → raw/poetry/<coll>/<vol>.json
        ↓
parse.py               → normalized/poetry/*.jsonl + database/poetry.db
        ↓
schema_v2.py           → provenance / quality_grade（增量回填）
relabel.py             → attribution_candidates / variant_candidates
crosscheck_100.py      → text_crosscheck + TEXT_CROSSCHECKED
quality.py / coverage.py → audit/*
```

### 6.4 实现边界（写清，避免下游误用）

| 边界 | 影响 |
|---|---|
| 四庫本无标点 | 15,866 条体裁「未定」；无法切句 |
| 四庫本字形（髙/眞/㑹） | 检索须用 `*_s` 简体列 |
| 四庫本有缺字 | 以 `{{SKchar|nnnn}}` 占位，转换时被删 → 个别句少字 |
| 晚晴簃各卷版式不一 | 同书内两套解析器并存 |
| 作者异名未归并 | 「陶潛／陶渊明」「陳思王植／曹植」查不到 |
| 朝代按集合/段名先验 | 跨代作者可能归错 |

## 12 自我审计

**1. 「374,918 条」这个数字会让人高估本库。**
其中 252,884 条是宋诗（占 67.4%），唐 55,628，其余各代加起来不到 18%。
**断代极不均衡**：隋 377、汉 544、辽 0、魏晋南北朝 4,354。
只报总数不报结构，就是误导。

**2. 我把「缺口 0」说成成果，但隋只有 377 首。**
「11 期都有作品」与「11 期都有代表性」是两件事。这个 0 缺口，含金量很低。

**3. 集韻这条我没做好，而且一开始差点写成「已取得」。**
10 卷 40 KB，平均每卷 4 KB，明显不是全文。是查了单卷体量才发现的。
**如果我只报「取得 5 部韵书词谱」，就是虚假陈述。**

**4. 古詩紀的作者解析改了三轮仍有残留。**
2,955 首作者为空，`簡文帝`、`元帝`这类谥号式写法与现代名不对应，
陶渊明、曹植按现代名查不到。**「名家缺口 2 位」这个结论本身就是解析缺陷的产物**，不是文献缺失。

**5. 四庫本无标点，导致 15,866 条体裁「未定」。**
这意味着**新补的四个朝代，其体裁结构无法统计**。补了 3.5 万首，却不能说清它们各是什么体。
这是本轮最大的功能性缺陷。

**6. 88 / 374,918 = 0.023%。**
`TEXT_CROSSCHECKED` 的覆盖率极低。我在报告里把它写成「唯一达到的核验等级」，
但读者容易忽略它的分母是 37 万。**下一轮若不做批量核对，这个比例不会改善。**

**7. 12 首 NOT_FOUND 里，可能有 2–3 首其实库里有，只是标题或作者写法不同。**
我没有逐首深挖，只按程序结果记为 UNKNOWN。这一条可能低估了匹配率。

**8. 我改了 `parse.py` 的入库方式（显式列名），但没有回归测试旧的 27 列数据是否完全等价。**
仅靠 5 项一致性自检（针对 `dup_status`）与总数对比。**字段级等价性未验证。**
