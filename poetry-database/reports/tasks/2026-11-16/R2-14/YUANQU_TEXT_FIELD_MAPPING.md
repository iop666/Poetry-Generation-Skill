# 元曲字段实际语义与「曲牌／宫调／曲文／科白」四段结构建议（R2-14 / C6）

> 依据：`works` 全量 10,685 条 `genre='曲'` 实测 + `raw/poetry/yuanqu/yuanqu.json` 11,057 条原文对照
> + `PRAGMA table_info(works)` + `tools/parse.py` 逐行阅读。
> 所有计数可用 `LOGS/C1_counts.json`、`LOGS/C2_stats.json`、`LOGS/C4_counts.json` 复核。

## 一、结论先行

`works` 里**没有任何一列专门存放曲牌、宫调或科白**。四类信息被上游压进了两个自由文本列：

```
title_raw  =  [剧名・][宫调/]曲牌 ・ 曲文前 ~30 字（在 32 字处被上游硬切）
text_raw   =  曲文后半截 + 科白（括注）+ 下一支曲牌的「幺」标记，混排
```

- `cipai` 列在 10,685 条元曲里**全为空**——曲牌从未被抽取，尽管它一直明摆在 `title_raw` 里。
- `chapter` / `section` / `volume` / `juan` / `record_locator` **全为空**（0/10,685）。
- `text_norm` 只是 `text_raw` 去标点的结果，**括注里的科白字仍在**，所以 `char_count` 含科白。

→ 现状不是一个「字段映射错了」的问题，而是**上游把四个语义段塞进了两个列**，导入侧原样继承。要做曲律分析，必须先把这四段拆开。

## 二、逐字段实测语义（`genre='曲'`，n=10,685）

| 字段 | 实际内容 | 证据 |
|---|---|---|
| `work_id` | `yuanqu:` + `sha1(author│title_norm│text_norm)[:12]`；同 id 冲突时追加 `-seq` | `parse.py` L321、L365 |
| `title_raw` | **混合列**，4 种形态（见第三节）。含曲文时被硬切在 32 字（33 字为句末标点延伸） | `title_len` 分布：32→1,425、33→235、其余 69（仅 1,729 条含曲文者） |
| `title_norm` | `title_raw` 去空白、去末尾括注、去首尾「·」；**曲文仍在** | `parse.py` `norm_title()` |
| `author_name` | 曲家名；杂剧多为作者，非剧中人 | 抽样 100 条作者均与 JSON `author` 全等 |
| `cipai` | **全空**（0/10,685） | `SELECT COUNT(*) WHERE cipai<>''` = 0。`parse.py` 只在标题含半角「·」时才填，而元曲用全角「・」 |
| `chapter`/`section` | 全空 | 同上 |
| `volume`/`juan`/`record_locator` | 全空 | 同上 |
| `text_raw` | **混合列**：曲文 + 科白括注 + 下支曲牌「幺」。按上游 `paragraphs` 数组逐段换行 | `line_count == len(text_raw.split('\n'))` 全等（10,685/10,685） |
| `text_norm` | `text_raw` 去标点、只留汉字；**括注内容保留** | `char_count == len(text_norm)` 全等（10,685/10,685） |
| `char_count` | = `len(text_norm)`，**含科白字**，不是纯曲文字数 | 同上；全库科白占汉字 6.0%（48,051/800,396），杂剧段远高于此 |
| `line_count` | = 上游 `paragraphs` 段数 | 全等 |
| `genre` | 恒为「曲」，`genre_basis='依集合先验'`——**不是逐条判定** | `parse.py` `COLLECTION_META['yuanqu']['genre_hint']='曲'` |
| `source_id` | 恒 `CP-YUANQU` | 10,685/10,685 |
| `seq` | 全局导入序号；元曲占 **327,703–338,387** 连续 10,685 号，**可用作导入顺序**（据此可反推 JSON 下标） | `SELECT MIN/MAX(seq)` |
| `variant_group`/`dup_status` | 只记重复/异文标记，**不合并文本** | `parse.py` L383-400 |
| `base_edition` | 全空；版本信息在 `provenance.base_edition='整理本（无底本声明）'` | `SELECT` 计数 |

## 三、`title_raw` 的 4 种形态（决定曲牌能不能取到）

| 形态 | 样例 | 条数 | 曲牌位置 | 宫调位置 |
|---|---|---|---|---|
| ① 纯曲牌 | `鹧鸪天` | 2,146 | 全串 | 无 |
| ② 剧名・宫调/曲牌 | `诈妮子调风月・仙吕/点绛唇` | 715（679 带剧名，36 无） | `/` 之后 | `/` 之前 |
| ③ 曲牌・曲文（硬切） | `尾声・春残连理枝，香冷合欢扇，好姻缘翻做了恶姻缘。还不彻相思债，` | **1,729** | 第一个「・」之前 | 无（5 条例外带 `南`/`北`） |
| ④ 「・」开头（曲牌丢失） | `・玉楼帘幕香风细，玉阑干杨柳依依。…` | **45** | **缺** | 无 |
| ⑤ 曲牌・南/北・曲文 | `好事近・南・谩说凤凰坡，怎比繁华江左？…` | 5 | 第一个「・」之前 | 第二个「・」之前（南/北） |

形态②是**套数/折的首支标记**，715 条里宫调位共 **24 种写法**，主流为 仙吕 253、双调 127、中吕 93、正宫 85、南吕 63、越调 40、商调 23、黄钟 9、大石调 4。
其中 `正官`(3)、`吕仙`(1)、`南宫`(1)、`王宫`(1)、`离调`(2) 是**错字**（正宫/仙吕/南吕/正宫/…），`烛影摇红`(1)、`太平令`(1) 是**曲牌误入宫调位**，另有 4 条带 `北` 前缀。抽取时需归一，但不得凭外部知识改写原文。

## 四、建议的目标结构（四段 + 剧名，共 5 个字段）

```
play_title   剧名      仅形态②有（679 条），如「诈妮子调风月」；无剧名者留空
gongdiao     宫调      仅形态②（`/` 前）与形态⑤（`南`/`北`）有；其余留空
qupai        曲牌      形态①②③⑤取「第一个・之前」；②取 `/` 之后；④留空并入 missing_qupai
lyric        曲文      形态③⑤ = title 中「・」之后 + text_raw 中非括注部分（按第六节规则拼接）
kebai        科白      text_raw 中所有 `（…）`/`(…)` 段，按出现顺序保留，不改字
```

### 4.1 抽取规则（可直接实现）

```python
# 1) 剧名 / 宫调 / 曲牌
if "/" in title:                       # 形态②
    left, right = title.split("・", 1) if "・" in title else ("", title)
    play, gd_qp = left, right
    gongdiao, qupai = gd_qp.split("/", 1)      # 宫调 / 曲牌
elif title.startswith("・"):           # 形态④
    qupai, gongdiao, play = "", "", ""
elif "・" in title:                    # 形态③⑤
    parts = title.split("・")
    qupai = parts[0]
    if parts[1] in ("南", "北"):
        gongdiao, parts = parts[1], parts[2:]
    lyric_head = "・".join(parts[1:]) if parts[1] not in ("南","北") else "・".join(parts[2:])
else:                                  # 形态①
    qupai = title
```

### 4.2 曲文 = 标题残段 + 正文残段（拼接有 3 个坑）

```python
lyric = lyric_head + strip_leading_qupai_marker(text_raw)
# 坑 1：不得按 32 字切。切点在上游，第 32 字往往落在词中间（「鸳衾」/「玉骢」）
# 坑 2：不得对 title 尾与 body 首做「去重」。
#       20 条是叠字续接（「恨绵」+「绵，情脉脉」），去重会吃掉真字
# 坑 3：45 条 body 以「幺」开头——那是下一支曲牌的标记，不是曲文。
#       其中 40 条标题停在半句，须剥掉「幺」再拼，否则拼出「玉骢幺嘶」
```

### 4.3 科白 ≠ 括号外内容

- 科白**全部**在括注里（`（正旦唱）`、`(末云)`、`(做叹科)`），共 2 种括号：半角 `(` 3,963 条含、全角 `（` 371 条含，**必须两种都匹配**。
  R2-12 只用半角 `LIKE '%(%唱)%'`，因此漏掉 293 条——这是 2,447 假象的成因。
- 694 条正文**以括注开头**（`(生上)…`），拼接曲文前要先剥掉。
- `char_count` 含科白，直接当「曲文字数」会系统性偏大；全库科白占汉字 **6.0%**。

### 4.4 第四种缺陷：标题/正文「垂直错位」（R2-14 新发现，1 例确认）

除了上面三种「横向」拼接问题，还存在**整条记录的标题与正文错配**——标题属于下一支曲牌，正文属于上一支：

```
json#108  关汉卿 | 尾・料应也不得为烟眷。有了神前咒怨…     paragraphs = []          ← 被 len<8 丢弃
json#109  关汉卿 | 双调・新水令                            paragraphs = 搅闲风吹散楚台云…  ← 实为「尾」的曲文

同一套数在「无名氏」区的副本：
json#10769 无名氏 | 尾・料应也不得为姻眷…                  paragraphs = 搅闲风吹散楚台云…  ← 标题与正文配对正确
```

即关汉卿副本里有一次 **1 条记录的向上错位**：`尾` 的正文被挂到 `双调・新水令` 名下，`尾` 自身留空后被导入过滤。
后果：`works` 中该行（`yuanqu:d25bc1835b74`）`title_raw` 与 `text_raw` 不同属一曲，且它的标题无句读，**不会被 B 判据（1,729）捕获**，也不在 41 条残篇里。

判定方法：只在「同一套数被两位作者重复收录」的 4 个块内逐条对齐两副本时可见（见 `LOGS/C7_yuanqu_cross_author_check.csv`，12 组中 4 组标题不同，均由此产生）。**全库是否有同类错位未全量扫描**——无第二副本时，单条记录无法自证标题与正文是否配对。

### 4.5 建议增加的判定列

| 列 | 取值 | 用途 |
|---|---|---|
| `text_origin` | `BODY` / `TITLE_MERGED` / `TITLE_ONLY` / `TRUNCATED_SOURCE` / `SHIFTED` | 让下游能排除拼接文本 |
| `qupai_status` | `OK` / `MISSING`（45 条） / `TRUNCATED`（`五煞`→`五` 之类） / `MISALIGNED`（错位，见 4.4） | 曲牌统计前过滤 |
| `prosody_ready` | `Y` / `N` | 41 条短段 + 1 条纯宾白 + 8 条句中截断 + 错位未校正者标 `N` |

## 五、明确不要做的四件事

1. **不要用 `cipai` 做元曲曲牌统计**——它 100% 为空，会把整批曲当「无曲牌」。
2. **不要用 `title_raw` 整串做曲牌 key**——1,729 条尾部粘着曲文，键必然失配；必须切「・」。
3. **不要按 32 字截 `title_raw` 当曲文**——32 只是上游列宽，切点在词中间，且 33 字另有 235 条。
4. **不要用 `char_count` 做「曲长」分层**——它含科白，且 1,729 条被截短，二者叠加会使短曲被严重高估。
