# EVIDENCE_TRACEABILITY_QUERY — 「为什么这个字归这个韵」的可追溯查询

## 1 目标

回答一个具体问题：**「某字在《广韵》为什么被归入某韵？」**
要求给出：原始转录行 → 解析算法 → 是否对过原图 → 版本 → 审查状态 → 若为推导则说明依据。

## 2 实现（四步链）

```
① source_locator    raw/books/guangyun/卷N.wikitext#offset
② raw_block         该 offset 处的原始转录片段（含〈〉注文）
③ algo_step         MARKER(　　) → HEAD(首字) → FANQIE(前两字+切) → YUN(最近的上游韵目)
④ evidence          DIGITAL_TRANSCRIPTION / FACSIMILE_IMAGE_DIRECT / INFERRED
```

## 3 示例（真实数据）

查询：东 → 广韵

| 项 | 值 |
|---|---|
| 结论 | 属卷一「一東」韵，小韵首，反切 徳紅切 |
| 原始转录行 | `一東〈獨用〉 … 東〈徳紅切東方也説文動也…十七〉` |
| 字符偏移 | `guangyun_head_classification_r2_11.offset`（entry `GY11-1-00000` 附近） |
| 算法 | 卷首韵目「一東」为锚 → 该字前有双全角空格 → 注文以「徳紅切」起首 → 注末「十七」 |
| 是否对图 | **是**（宋刻本 SBL015 p011 右半叶，`raw/r2_12/facsimile/GUANGYUN_p011.jpg`） |
| 版本 | 转录＝四库本（维基文库）；图像＝宋孝宗朝初期刊（静嘉堂藏） |
| 证据等级 | `PRINTED_EDITION_DIRECT`（反切与字数均核对） |
| 审查状态 | 主 Agent 目视 + 版本差异记录（崇字切下字存疑） |

查询：崇 → 广韵

| 项 | 值 |
|---|---|
| 结论 | 一東韵小韵首，转录作「鋤功切」 |
| 分歧 | 影印本似作「鋤弓切」 |
| 状态 | `DIFFERENCE_PENDING`，**不裁定** |
| 影响 | 「弓」三等、「功」一等，影响等呼判断；在未定前该条不得用于等呼推导 |

## 4 无法回答的情形（必须显式返回）

| 情形 | 返回 |
|---|---|
| 该字非小韵首 | `NO_INDEPENDENT_FANQIE`（只有韵目，无读音） |
| 韵目未定位 | `YUN_UNRESOLVED`（本轮广韵 0 条） |
| 只有集韵而广韵无 | `NOT_IN_BOOK`（不得用集韵补广韵） |
| 上古音 | `UNAVAILABLE` |
| 影印未核 | `IMAGE_UNVERIFIED`（默认状态，除 9 条） |

## 5 这套接口给下游的承诺与警告

**承诺**：任何一条韵部归属都能回到一行原始转录；任何一条反切都能说明是转录还是对图所得。

**警告**：
1. 99.9% 的广韵记录仍是 `DIGITAL_TRANSCRIPTION`，转录本身可能含 GD-029 式列序交错；
2. 「归入某韵」是**转录结构**的结论，不等于「中古音值」；
3. 不得把本接口的输出直接当作创作规则（那需要 Phase 3，尚未授权）。
