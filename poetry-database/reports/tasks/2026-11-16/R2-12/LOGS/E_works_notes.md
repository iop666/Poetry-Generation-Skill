## 一、开工前对前提的复核（4 条中 3 条需要修正）

| 交办说法 | 实测 | 结论 |
|---|---|---|
| `SELECT count(*) FROM works WHERE text_raw LIKE '%一作%'` 报 339 条 | 339 ✅ | 数字对，但这是 **text_raw** |
| 「works.text_norm 混入校记 339 条」 | **text_norm 中含「一作」字样的只有 15 条** | ❌ 口径错。339 是 raw 数；norm 里真正残留「一作」二字的是 15 条 |

| 作者名截断「张」→「张昇」 | ✅ 库内确实有 `author_name='张'` 4 条，均为宋词；但**库内不存在 `张昪/张昇` 任何写法**，无法闭环 | 只能给 MERGE_UNCERTAIN |
| `char_count` 被污染（如 196 vs 实际 176） | ✅ `char_count` 与 `length(text_norm)` **在全部 375,399 行完全相等**（`count(*) WHERE char_count != length(text_norm)` = 0）。所以 char_count 不是独立算错，而是**继承 text_norm 的污染**。`tang300:044721b35875`（將進酒）char_count=196、norm 196、重建后正文 **176** 字 ✅ | 机制确认 |

**核心修正**：真正的问题不是「norm 里混进了『一作』两个汉字」，而是归一化脚本对「（X 一作：Y）」这类校记处理不干净，产生两种反向错误：

1. **注头回流**（116 行）：删掉「一作：Y）」但把 X 留下 → norm 变长，句末多一个词（「王孫歸不歸**明年**」）；
2. **正文被当校记删掉**（184 行）：把 `X（一作「Y」）` 整段删掉（连 X 一起），或把诗句里的「一作」（如「相看一作秦吳別」）误认为校记 → norm 变短，正文少字（「相看**別**」）。

分类口径（互斥）：看「一作」字符串的性质，而非损害程度。

| classification | 条数 | 含义 | 本批实际情形 |
|---|---|---|---|
| EDITORIAL_NOTE | 143 | 编者校记 | 均为「X（一作「Y」）」式行内夹注，norm 把 X 连带删除 |
| MIXED_BODY_AND_NOTE | 141 | 正文与校记黏连 | 116 条注头回流（norm 变长）+ 15 条等长替换 + 10 条既回流又丢字 |
| POEM_BODY | 42 | 「一作」本属诗句 | 31 条正文被误删（丢字），11 条 norm 未动（正确） |
| VARIANT_NOTE | 13 | 异文校记（已正确剥离） | norm 干净，无需修复 |
| AUTHOR_NOTE / PAGE_HEADER / PAGE_NUMBER / OCR_NOISE | 0 | — | 本批 339 条中未出现 |
| UNCLASSIFIED | 0 | — | 全部定位成功 |

污染方向核账（合计 339）：

- norm 比正文**长**（注头回流）：**116**
- norm 与正文**等长但内容不同**（注头替换了正文词）：**15**
- norm 比正文**短**（正文丢字）：**184**
- norm 与正文**完全一致**（无损害）：**24**（13 VARIANT_NOTE + 11 POEM_BODY）

### 标记构成（339 条内并存统计）

`一作` 253 · `一作+括号外一作` 59 · `一作+項校` 17 · `一作+案` 6 · `一作+或作` 2 · `一作+一本作` 1 · `一作+校改` 1。

即：**全部 339 条都以「一作」为主标记**，`一本作`/`校改`/`或作`/`項校`/`案` 只是同条内的副标记，不存在「只有某本作而没有一作」的条目（`text_raw LIKE '%某本作%'` = 0）。

### 判定方法

1. 用 `RE_NOTE` 抓出 raw 中所有 `（…一作…）` 段落，拆成 `head`（注头 X）与 `variant`（异文 Y）；
2. `body = raw` 删除全部校记段 → 去括号、去标点得 `sug`；
3. `difflib.SequenceMatcher(sug, text_norm)` 求 opcodes：
   - norm 多出的段 = 注头回流（长度增加）；
   - norm 缺的段 = 正文丢字（长度减少）；
4. 括号外出现的「一作」单独人工判读（共 72 处），逐条给出证据（见 `_e1_final.json` 与 CSV 的 `evidence`）。

### 括号外「一作」的两种性质（72 处，全部人工判读）

- **正文用词**（42 条 POEM_BODY）：如「相看一作秦吳別」（王安石《送王覃》）、「狂風一作浪如屋」（任希夷《盤沙行》）、「一作劍關客」（陸游《思蜀》）、「一作江南守」（張九齡《戲題春意》）——「一作」=「曾作/竟作」，是诗句的一部分。
- **编者按语/著录**（其余）：如「《全唐詩》卷八百六十一作李夢符詩」、「校文中均以『一作某』代指該卷」、「詩題：原無題首句：…」。

### 无法判定

0 条。339 条全部落到 4 个类别内。但**分类置信度**只有 HIGH 134 / MEDIUM 205：MEDIUM 集中在「校记已剥离但连带删掉正文字」的 143 条——类型无争议，只是损害边界需逐条看，已在 evidence 写明被删字。

## 三、E2：正文重建建议

输出 `WORKS_TEXT_REVISIONS_R2_12.csv`，**328 行**，`applied` 全为 `NO`。

- `old_text_norm` 完整保存原值（含长文本，未截断；最长一行 1,000+ 字）；
- `suggested_text_body` = raw 去掉校记、去括号、去标点后的正文；
- `removed_segments` = 被移除的校记原文（多段用 ` | ` 分隔）；
- `confidence`：**HIGH 206 / MEDIUM 53 / LOW 69**。

置信度规则（可复核）：

1. 体裁为定长（五绝 20 / 七绝 28 / 五律 40 / 七律 56）且重建后字数恰好等于期望 → HIGH；
2. 括号配平 + 全部注头解析成功 + 「norm 多出的字全部来自校记字符集」→ HIGH（覆盖古体、乐府、词等不定长体裁）；
3. 括号配平 + 解析成功但字符集校验不过 → MEDIUM；
4. 括号不配平、注段解析失败、或该条本身是著录/按语而非诗 → LOW。

**明确保留、不删的括号内容**：诗题小序、词牌题注、作者自注（「時年十七」「有序」「幷序」等）不在 339 条范围内，未做任何删除；339 条中被删的括号内容全部是「一作/某本作/項校」型校勘夹注，逐条见 `source_text` 字段。

**边界拿不准的例子（已降级）**：

- `tang300:044721b35875` 將進酒：一条校记内嵌三组异文「（不足貴 一作：何足貴；不復醒 一作：不願醒/不用醒）」，分隔符混用「；」和「/」，只能整段删，MEDIUM；
- `tang:1e1701929a42` 答高越、`tang:35d608c1007a` 出雲州書情寄兩敕使：正文其实是编者按语，不是诗，删了校记也不是「正文」，LOW；
- `tao:1c92e02b8348` 歸園田居·其四：raw 内嵌 `<ref>曾本云，一作樹木殘根株。</ref>`，属 HTML 校勘标签，删标签后正文完整，但标签体系与其它条目不同，LOW。

## 四、E4：500 条分层抽样

### 抽样 SQL 全文

```sql
-- 分层定义（7 层）
-- 唐诗       : dynasty='唐' AND genre<>'词'
-- 宋诗       : dynasty='宋' AND genre<>'词'
-- 宋词       : dynasty='宋' AND genre='词'
-- 元曲       : dynasty='元'
-- 明清诗词   : dynasty IN ('明','清')
-- 六朝诗     : dynasty='魏晋南北朝'
-- 先秦两汉韵文: dynasty IN ('先秦','汉魏')

-- 每层先随机取 600 条候选池
SELECT work_id,title_norm,author_name,text_raw,text_norm,char_count
FROM works WHERE <层条件> ORDER BY random() LIMIT 600;

-- 池内按 3 个维度切 8 个单元，每单元配额 max(10, 80/单元数)：
--   has_punct  = text_raw 含 [，。！？；：、]
--   is_long    = char_count >= 80
--   has_tnote  = title_raw 含 [（(] 或含「有序/幷序/并序/題注」
-- 不足 80 条时从该层候选池随机补齐

-- 重复判定（20 字前缀全库索引，一次扫描建字典后 O(1) 查询）
SELECT work_id, substr(text_norm,1,20) FROM works WHERE length(text_norm)>=20;
```
