# C3 — 214 个 COUNT_MISMATCH 来源的成因定位（R2-15）

脚本：`LOGS/C3_count_mismatch.py`（只读，零写入）
机器统计：`LOGS/C3_stats.json`
清单：`SOURCE_COUNT_MISMATCH_214.csv`（214 行）

---

## 1 分母来源与复核

- 214 这个数字来自 `R2-14/LOGS/seq2_verify.csv`：818 个可用来源中
  `COUNT_MATCH 604 / COUNT_MISMATCH 214`，本轮**逐个重算后 214 个全部落在新清单里**，无增无减。
- 重算方法：`works` 按 `source_id` 计数 vs `sources.local_path` 指向的 JSON 数组长度
  （dict 根取最大 list 字段）。两者独立于 R2-14 的旧表。

## 2 总体形态：214/214 都是「库内少于文件」，没有一条反向

| 项 | 值 |
|---|---|
| 214 源 JSON 记录总数 | 212,348 |
| 对应入库作品总数 | 210,044 |
| 缺口合计 | **2,304 条（1.09%）**，其中 2,303 条为 <8 字残句 |
| 缺口方向 | works_n < json_n：**214 / 214**（无 works > json 的情形） |
| 单源缺口中位数 | 4 条（最小 1，最大 372） |
| 缺口分布 | 1–5 条 127 源 / 6–50 条 80 源 / >50 条 7 源 |

方向单一是关键结论：**不存在「重复登记」或「文件被换成更小的版本」**——
若发生替换或重复登记，必然出现 works_n > json_n 或整片错位，实测为零。

## 3 根因：导入器丢弃「正文 CJK 字数 < 8」的残句

对每个来源计算 `short = 正文汉字数 < 8 的记录数`，再验证 `json_n - short == works_n`：

| 结果 | 来源数 |
|---|---|
| **完全相等（可精确复算）** | **213 / 214** |
| 相等但多丢 1 条 | 1（`CP-TANG-58`） |
| 不相等 | 0 |

即：每一个缺口都能被同一句话解释——**上游 JSON 里的残句/断句（正文不足 8 个汉字）在导入时被过滤**。
全库口径验证（819 个有作品的来源）：**813 个**满足 `json_n - short == works_n`；
其余 5 个是结构化例（`CP-SHIJING`/`CP-CHUCI`/`CP-NALAN` 的正文嵌套在别的字段、
`CP-TANG300` 根节点为 dict、`WS-GUSHIJI-139` 有 1 条 <8 字却被保留），与本次 214 集无关。

### 3.2 唯一例外：CP-TANG-58（1 条）

`raw/poetry/tang/poet.tang.57000.json` 第 447 条「句 三」無名氏
「綠（一作「流」）水溢金塘。」13 字 → 去校记括注后仅 5 字，被丢弃；
而同文件第 16、25 条同样含校记却保留了。说明导入时的字数判定对「一作」类括注处理不一致，
属**单条规则毛刺**，不影响整体结论。已在该行 `note` 标注 `json-short=583 vs works=582`。

## 4 是「过滤」还是「错位」？——抽样验证

对缺口最大的 10 个来源，各取前 3 条 works 的 `title_raw` 回查 JSON 数组下标：

- **30/30 全部命中**，且下标严格单调递增（`monotonic=Y`）；
- 没有任何一个来源出现「首条就对不上」的错位特征。

结论：**是过滤，不是错位**。缺口集中在数组后段/夹在中间，前后条目的相对顺序未变。

## 5 可恢复性与建议

| 判断 | 说明 |
|---|---|
| 可定位性 | **高**：`json_n - short` 口径逐源精确复算，213/214 零误差 |
| 可恢复性 | **技术上可恢复**（残句在 JSON 里完好，可原样重放） |
| 是否建议恢复 | **不建议整体回灌**：2,304 条均为正文 <8 字的断句/残句，回灌会把「句」「残句」类噪声重新引入，并破坏现有 8 字下限的一致性 |
| 建议动作 | ① 把「正文 CJK<8 丢弃」写进导入器文档与单测；② 输出 `DROPPED_TEXT_LT8.csv`（2,303 条 + CP-TANG-58 的 1 条例外）作为可复核清单；③ 对 `CP-TANG-58` 的括注字数规则单独修正 |

**唯一允许写入定位候选的口径**：`(source_id, json_index)` 二元素定位——
因为 30/30 抽样都能按 `title_raw` 唯一命中且单调，可反推 json_index。
模糊匹配（相似度、前缀）一律不得升级为定位候选。
