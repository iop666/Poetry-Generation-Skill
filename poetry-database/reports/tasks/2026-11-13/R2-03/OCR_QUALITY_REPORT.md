## 一、先说引擎：本轮**没有**用上 PaddleOCR-VL-1.6

任务要求使用 PaddleOCR-VL-1.6 API。实际核查结果：

| 检查项 | 结果 |
|---|---|
| 本地是否安装 paddleocr / paddlepaddle | **否**（`import paddleocr` 失败） |
| 环境是否提供 OCR 端点 | 有 `WORKBUDDY_VLM_CHAT_URL`（模型 `kinfra-office-agent`），是**通用视觉模型代理**，非 PaddleOCR-VL |
| 该端点是否可用 | **否**。按 OpenAI 兼容格式、`prompt` 格式、多种鉴权头各试数次：无 token → 401；带 token → 400（空体）。会话 token 短时失效，无法稳定调用 |
| 是否改用其他在线 OCR | **否**（不得私换服务，也不得把书页上传第三方） |

**结论：PaddleOCR-VL-1.6 在本轮环境中不可用，我没有伪造"已用 PaddleOCR"的记录。**

替代方案：**macOS 内置 Vision 框架**（`VNRecognizeTextRequest`），完全离线、零 token、不上传。
自写 `tools/ocr_vision.swift`（约 70 行）编译为命令行工具，供 `tools/ocr_pdf.py` 调用。
每页记录 `engine="macos-vision-rev2"`，可与 PaddleOCR 结果区分，后续若拿到 PaddleOCR 可重跑对照。

## 二、为什么锁 rev2：一次可复现的选型实验

Vision 有多个模型版本（revision）。同一页（诗词格律 PDF 第 41 页，印刷 33 页）实测：

| 配置 | 「平对仄」是否识别正确 | 「瓜」（平之误识）出现次数 | 平均置信 |
|---|---|---|---|
| rev3 + zh-Hant + 关闭语言纠正 | ✗（识为「平对厂」） | **9** | 0.58 |
| rev3 + zh-Hans + 关闭语言纠正 | ✗ | 9 | 0.58 |
| **rev2 + zh-Hant + 关闭语言纠正** | **✓** | **0** | **0.93** |
| rev1 + zh-Hant | 乱码（拉丁字母） | 0 | 0.31 |

rev3 会把「平」识成「瓜」、「仄」识成「厂」。这两个字是格律规则的本体，错一个就毁一条规则。
故锁定 **rev2**，并**关闭语言纠正**（`usesLanguageCorrection=false`）——开启后模型会把「平」强行改成常用字，等于改写原文。

这一条是本轮最重要的工程结论之一：**OCR 不能只看"是否通顺"，要看关键符号是否正确。**

## 五、已知的失败模式（必须避开）

### 5.1 词谱表格页不可用

诗词格律概要卷下「词牌和词谱」用 ○● 标平仄。OCR 把 ○ 识成「四」「因」「西」「囚」，例如：

| OCR 输出 | 实际 |
|---|---|
| `四仄平平仄。` | `○仄平平仄。` |
| `因仄平平平仄仄。` | `○仄平平平仄仄。` |
| `西仄平平瓜。` | `○仄平平○。` |

**处理办法：本轮的词谱数据一律不取自此书**，改用《唐宋词格律》PDF 的文字层（其符号为 －｜＋，直接可读）。
这不是取舍偏好，是因为后者的符号没有经过 OCR。

### 5.2 版心页码被拆开

正文页首行常只有一个残缺数字（如「3」，实为「23」被拆成两段文本对象）。
因此**页码一律记 PDF 物理页**，读者可按页打开 PDF 复核；不提供猜测的印刷页码。
