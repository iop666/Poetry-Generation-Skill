## 三、采集过程中实际遇到并解决的五个技术障碍

这些不是事后补记，是本轮真实卡住过的地方。

### 3.1 urllib 对 jsdelivr 卡在 read 阶段

**现象**：`urllib.request.urlopen` 请求 `cdn.jsdelivr.net` 的 400KB 文件，读取阶段超时（45 秒收 0 字节）；
同一 URL 用 `curl` 只需 1.25 秒。

**处理**：采集器改用 `curl` 子进程传输，理由写进代码注释。
**未做**：没有去改系统代理或伪造 header，属正常 HTTP 客户端差异，不是绕过限制。

### 3.2 URL 中 `@master` 被编码成 `%40` 导致 400

**现象**：首轮 20 个文件"下载成功"，实际存的是 63 字节的错误页
`Invalid URL. The URL structure is /gh/user/repo@version/file.js`。
原因：百分号编码白名单里漏了 `@`。

**处理**：白名单加 `@`，并**删除全部错误页重采**。
**教训**：只看「文件存在且非空」会把错误页当成成功。现采集器校验 HTTP 状态码 + 字节数，但仍未校验内容是否为目标数据 —— 这是残留风险（见报告 09）。

### 3.3 维基文库的「目录页」与「重定向页」

**现象**：
- `滄浪詩話` 只有 357 字节，内容是五卷目录；
- `聲律啟蒙` 只有 25 字节，是 `#redirect[[聲律啓蒙]]`（启／啓 异体）；
- `詩品` 总页只有序，正文在三卷分页。

**处理**：新增 9 个补充来源（`SUP-*`），分别抓取卷页与重定向目标。
**后果**：如果不做这一步，就会有「文件非空、字数极少」的假成功。

### 3.4 模板吞字：`{{ProperNoun|唐}}` 被整段删除

**现象**：首版转换器把 wikitext 模板一律删除，导致《沧浪诗话》出现
「以**汉魏晋盛**为师，不作**开元天宝**以下人物」——「唐」字全部消失。
原文应为「以汉魏晋盛唐为师，不作开元天宝以下人物」。

**处理**：模板处理改为「保留第一个位置参数」：
`{{ProperNoun|唐}}` → 唐；`{{參|辨|一作「辯」}}` → 辨；`{{header|title=…}}`（具名参数）→ 删。
修改后同句恢复为「以汉魏晋盛唐为师」。

**这是本轮最有价值的一次自查**：如果不逐句读，这个缺陷会一路带进知识提取。

### 3.5 抽样偏差：名家集体缺席

**现象**：初版对全唐诗 58 片均匀抽 12 片，结果**杜甫只有 490 首、李白 55 首、苏轼 0 首**。
原因：全唐诗按卷序排，同一作者的诗集中在相邻分片，均匀抽样必然整块漏掉。

**处理**：改为**全量取入**（全唐诗 58 片、全宋词 22 片）。杜甫 1,528、李白 1,240、苏轼 356。

**残留**：全宋诗 26 万首仍只取 4 片（约 4,000 首），导致姜夔 0 首。
