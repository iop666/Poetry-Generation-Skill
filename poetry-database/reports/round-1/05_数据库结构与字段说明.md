# 05 数据库结构与字段说明

**技术栈**：SQLite（`database/poetry.db`，95.4 MB）＋ JSONL 目录（`catalog/`）＋ 原始文件（`raw/`）＋ 规范化文本（`normalized/`）。
零第三方依赖，Python 标准库即可复现全部构建。

---

## 一、目录结构

```
poetry-database/
├── database/poetry.db          SQLite 主库（7 张表）
├── raw/
│   ├── poetry/<collection>/    103 个 JSON 原文件（原样保存，不改一字）
│   └── books/                  25 个 wikitext 原文件（原样保存）
├── normalized/
│   ├── books/                  25 个去标记后的纯文本（带来源头）
│   └── poetry/<collection>.jsonl  按集合导出的全量记录
├── catalog/                    JSONL 目录（可脱离 DB 使用）
│   ├── authors.jsonl           5,286 位作者
│   ├── sources.jsonl           128 个来源
│   ├── collections.jsonl       11 个集合
│   ├── books.jsonl             13 种现代专著（未采集）
│   ├── cards.jsonl             103 张研究卡
│   └── works_sample.jsonl      前 2,000 条作品（样本；全量见 normalized 与 DB）
├── research/
│   ├── book_reading_notes/     5 份阅读记录
│   └── poetry_analysis/        cards_auto.md（103 首）、cards_manual.md（12 首精读）
├── audit/                      采集、解析、质量、覆盖四类日志与报告
├── sources/manifest.json       采集合约（采什么、什么许可、可靠性如何）
└── tools/                      6 个可复跑脚本
```

## 二、七张表

| 表 | 行数 | 作用 |
|---|---|---|
| `sources` | 128 | 每个来源一行：名称、类别、URL、许可、可靠性、维护者、本地路径、字节、解析状态 |
| `collections` | 11 | 采集集合（tang/songci/huajianji…）及其朝代、作品数 |
| `books` | 13 | 现代版权专著书目（**仅登记，未采集**） |
| `authors` | 5,286 | 作者、朝代、作品数、所属集合、自动标注标记 |
| `works` | 90,279 | 作品主表（27 列） |
| `variants` | 18,806 | 重复组与异文组的成员关系 |
| `read_log` | 0 | 阅读进度登记（本轮的阅读记录写在 Markdown 笔记里，未回填此表——**这是一处未完成**） |

## 三、`works` 表字段

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `work_id` | TEXT PK | 生成 | `<collection>:<sha1(author+title+text)[:12]>` |
| `title_raw` | TEXT | 原文 | 原始标题，未改 |
| `title_norm` | TEXT | 推导 | 去空白、去末尾括注，**可回溯到 title_raw** |
| `author_name` | TEXT | 原文 | 缺失时：`caocao` 集合补「曹操」，其余补「佚名」 |
| `author_id` | TEXT | 生成 | `A:` + sha1(名)[:10] |
| `dynasty` / `era` | TEXT | 集合先验 | 如「唐」「五代」；**非据史传核定** |
| `collection` | TEXT | 采集 | 集合名 |
| `genre` | TEXT | 推导 | 11 类之一（见报告 04） |
| `genre_basis` | TEXT | 推导 | 判定依据，如「8句×7字，句式整齐」 |
| `cipai` | TEXT | 原文/推导 | 词的词牌；纳兰集从「长恨歌·题」的「·」前取 |
| `chapter` / `section` | TEXT | 原文 | 如诗经「国风」「周南」；唐诗三百首的体裁分组 |
| `text_raw` | TEXT | 原文 | **原始分行原貌，永不改写** |
| `text_norm` | TEXT | 推导 | 去标点、去校记、只留汉字；`strip_notes()` 可复算 |
| `line_count` / `char_count` | INTEGER | 推导 | 行数／汉字数 |
| `source_id` | TEXT | 采集 | 指向 `sources`，**零缺失** |
| `volume` | TEXT | 原文 | 卷次（多数集合为空） |
| `seq` | INTEGER | 生成 | 入库序号 |
| `variant_group` | TEXT | 推导 | `G:`=完全重复组，`V:`=异文候选组 |
| `dup_status` | TEXT | 推导 | `UNIQUE` / `KEPT` / `DUPLICATE` |
| `verify_status` | TEXT | 推导 | `AUTO`（自动标注，未核验）/ `VARIANT_PENDING`（异文待比对） |
| `auto_meta` | INTEGER | 生成 | 1＝字段为程序推导 |
| `author_s` / `title_s` / `text_s` | TEXT | 推导 | OpenCC t2s 简体索引，供繁简通检 |

## 四、可追溯性（三层结构的落地）

任务书要求「三层必须能相互追溯」。本库的实现方式：

| 层 | 落在哪 | 追溯路径 |
|---|---|---|
| 第一层 原始文献 | `raw/`（128 个原文件，字节级不改） | 由 `sources.local_path` + `sha256` 定位 |
| 第二层 结构化数据 | `works` / `normalized` | 每条 `work_id` 带 `source_id`，可回到原始文件与具体条目 |
| 第三层 研究结论 | `research/*.md` | 每条引文标注书名＋行号（如「文镜秘府论 行 89」），可回到 `normalized/books/*.txt` |

**反例自检**：若知识库里有一条规则却找不到出处，即违反第三层约束。本轮报告 03 第五节已按此自查。

## 五、构建命令（从零复现）

```bash
cd poetry-database

python3 tools/build_manifest.py    # 1. 生成来源清单（128 源）
python3 tools/acquire.py           # 2. 按清单采集（幂等，已存在则跳过）
python3 tools/convert_books.py     # 3. wikitext → 纯文本（25 种文献）
python3 tools/parse.py             # 4. 解析入库（JSONL + SQLite）
python3 tools/quality.py           # 5. 质量审查（10 项）
python3 tools/coverage.py          # 6. 覆盖率 + 103 张研究卡
```

依赖：Python 3.11+、`curl`、`opencc-python-reimplemented`（仅繁简索引与韵书沿用）。
六个脚本全部幂等，可重复执行。

## 七、设计取舍（可被质疑的地方）

| 取舍 | 理由 | 风险 |
|---|---|---|
| 正文不存标点 | 便于按字数判体、按句切分 | **丢失原标点**，无法还原句读；`text_raw` 保留原始分行可部分补救 |
| 体裁用「句数×句长」推断 | 可批量、规则透明 | 五言古绝会被判五绝；20 句以上长诗一律「古体诗」 |
| 朝代按集合先验赋值 | 数据集本身无朝代字段 | 跨代作者（如由唐入宋）会归错 |
| 作者不做异名归并 | 避免误合（「李白」与「李太白」） | 5,286 位作者中必有重复人格 |
| 繁体不作统一转简 | 保留原文 | 繁简混排，检索须用 `*_s` 列 |
| `read_log` 空表 | 阅读证据写在 Markdown | 机器不可查阅读进度 |

上表六项，都是**为了先跑通而做的让步**，不是最终设计。
