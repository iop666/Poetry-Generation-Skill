# 字符统计口径说明（避免误判为数据丢失）

本目录的 `manifest.json` 有两个字符字段，口径不同：

| 字段 | 定义 | 用途 |
|---|---|---|
| `full_chars` | 该单元覆盖的 PDF 页，逐页 `clean()` 后字符数之和 | 衡量「页内可解析文本总量」 |
| `evidence_chars` | 从上述文本中按关键词筛出的证据段字符数（上限 5,000/章） | 衡量「进入引文核对的材料量」 |

`full/` 下的 Markdown 不是把 `full_chars` 原样写出，而是经 `paragraphs()` 处理：
按空行分段、合并行内换行、**丢弃不足 12 字的短行**（页眉、页码、图注、公式残片）。

因此存在固定差额：

- 17 个单元 `full_chars` 合计 **128,873**（可 100% 复算）
- `full/*.md` 实际字符 **107,351**
- 差额 **21,522** = 被 `paragraphs()` 丢弃的短行 + 段落化处理的换行差异

**这不是文件被改、也不是 manifest 未更新。** 逐单元复算见
`reports/tasks/2026-11-20/R2-15/COPYRIGHT_CHARCOUNT_DIFF.csv`。
